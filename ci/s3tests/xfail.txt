# Ceph s3-tests cases this implementation is known to fail.
#
# WHAT THIS FILE IS
#   The tolerated set. `ci/s3tests/report.py` treats a failing case listed here as KNOWN and
#   a failing case that is absent as a REGRESSION that fails the weekly job. A listed case
#   that now passes is reported as FIXED so the list shrinks.
#
# THE RATCHET
#   The list may shrink in any pull request. It may only grow in a pull request that also
#   raises the generation below by one, and `scripts/check_xfail_ratchet.sh` refuses every
#   other addition. That is deliberate friction: a tolerated failure is a promise nobody
#   made, and the cheapest way to turn this job green is to paste the failures into it.
#
# EXCLUSIONS
#   `<case-id> excluded <owner issue URL> <reason>` takes a case out of the verdict entirely:
#   it is still run and reported, but neither KNOWN, FIXED nor REGRESSION. It is for a case whose
#   outcome does not reproduce from run to run, and it follows the rules for an excluded SDK in
#   ci/mint/baseline.txt: the owner is an issue in rustfs/gateway or rustfs/backlog, the reason is
#   at least three words, and adding one needs the generation raised by exactly one. None is
#   listed today: the two cases generation 2 excluded became deterministic (REFRESH 2026-09-30).
#
# HOW TO PROPOSE A NEW BASELINE
#   Run the workflow with `mode: record`. It writes xfail.proposed.txt and outcomes.proposed.txt
#   as run artifacts. Attribute every group to an owner before landing it, together with
#   ci/s3tests/outcomes.txt, the per-case record of the same run.
#
