# MAP — rustfs-gateway-dialect-rustfs-admin

Agent entry point. File → responsibility → when you need to open it.

Everything under `src/ops/` and `src/table.rs` is generated by `cargo xtask rustfs-admin-dialect`
from `crates/goldens/src/migration_inventory/rustfs_admin_routes.json`. Never edit it by hand:
change the inventory or `xtask/src/rustfs_admin_dialect.rs`, then regenerate.

| File | Responsibility | Read it when |
|---|---|---|
| `src/lib.rs` | Crate root: re-exports the dialect, the shared shapes and the generated tables. | Finding the public surface. |
| `src/admin.rs` | The shapes every operation shares: `AdminResponse`, the spec and floor constructors, the body decoders and the response encoder, `AdminOperation` and `OperationFold`. | Changing what a handler receives or answers, or how every operation is authorised. |
| `src/record.rs` | The shapes of `ROUTES` and `PENDING`: what each operation was generated from, and the groups not migrated yet. | Reporting which admin routes the gateway serves. |
| `src/dialect.rs` | The two path-prefix claims, the overlay, and `rustfs_admin_dialect()`, which declares every generated operation. | Installing the dialect, or a claim changes. |
| `src/table.rs` | Generated: the overlay rows, `ROUTES`, `PENDING` and `fold_every_operation`, each listing the operations in inventory order. | Checking which routes are migrated and which groups are pending. |
| `src/ops/mod.rs` | Generated: mounts one module per operation. | Never; read one operation file instead. |
| `src/ops/<operation>.rs` | Generated: one operation's name, rows, action, specification, floor, codec, overlay row and record. | Reviewing one route's declaration. |
| `tests/integration.rs` | The crate's one test target: every declared route routes, with and without the dialect, and every declaration matches its record. | Changing a row, a selector, or a shared shape. |

## Verify

```bash
cargo xtask verify --crate rustfs-gateway-dialect-rustfs-admin
cargo xtask rustfs-admin-dialect --check
```
