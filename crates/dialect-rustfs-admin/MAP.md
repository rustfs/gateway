# MAP — rustfs-gateway-dialect-rustfs-admin

Agent entry point. File → responsibility → when you need to open it.

Everything under `src/ops/` and `src/table/`, and `src/table.rs`, is generated by `cargo xtask rustfs-admin-dialect`
from `crates/goldens/src/migration_inventory/rustfs_admin_routes.json` and ADR-0039. Never edit it by hand:
change the inventory or `xtask/src/rustfs_admin_dialect.rs`, then regenerate.

| File | Responsibility | Read it when |
|---|---|---|
| `src/lib.rs` | Crate root: re-exports the dialect, the shared shapes and the generated tables. | Finding the public surface. |
| `src/admin.rs` | The shapes every operation shares: `AdminResponse`, the spec and the two floor constructors (privileged, and the anonymous bootstrap's), the body decoders and the response encoder, `AdminOperation` and `OperationFold` for the claimed operations, `ExtensionOperation` and `ExtensionFold` for the S3-shaped extension rows. | Changing what a handler receives or answers, or how every operation is authorised. |
| `src/record.rs` | The shapes of `ROUTES`, `PENDING`, `STAYING`, `FORM_ROUTES` and `EXTENSION_ROUTES`: what each operation was generated from (its subject rule, bucket binding and anonymous opt-in included), the groups not migrated yet, the routes that stay with RustFS, the form-claimed route, and the extension routes. | Reporting which admin routes the gateway serves. |
| `src/dialect.rs` | The six path-prefix claims (admin API and table catalog, each under its RustFS and compat spelling, and the two profiling triggers), the overlay, and `rustfs_admin_dialect()`, which declares every generated operation — the claimed ones inside the claims, the eight extension ones as S3-table rows (rustfs/backlog#2753) — the two authenticated fallbacks and the STS endpoint behind its form claim (ADR-0041). | Installing the dialect, or a claim changes. |
| `src/table.rs` | Generated: `PENDING`, `STAYING`, `FORM_ROUTES`, `EXTENSION_ROUTES` and the source commit, and re-exports of the lists below. | Checking which groups are pending, stay with RustFS, are form-claimed, or are extension rows. |
| `src/table/{overlay,routes,fold}.rs` | Generated: the overlay (both fallbacks, the STS endpoint and the extension rows included), the inventory-only `ROUTES`, and the `fold_every_operation` and `fold_every_extension` walks. | Checking which routes are migrated; never edited. |
| `src/ops/mod.rs` | Generated: mounts one module per operation. | Never; read one operation file instead. |
| `src/ops/<operation>.rs` (including `admin_fallback`, `admin_v4_fallback` and `sts_form_post`) | Generated: one operation's declaration and codec; native operations also carry an inventory record, while fallbacks carry their fixed handler; `sts_form_post` is RustFS's STS endpoint behind the dialect's form claim, with its floor and Legacy-compat record (ADR-0041). | Reviewing one route's declaration. |
| `src/ops/{reset_bucket_replication,get_replication_reset_status,get_replication_metrics_v2,get_replication_metrics,check_replication,invoke_object_lambda,listen_notification,listen_bucket_notification}.rs` | Generated: one S3-shaped extension operation each (rustfs/backlog#2753): its S3-table row — method, target and one query discriminator, ahead of every standard row of its cell — every overlap that placement declares, its IAM action, privileged floor, bodyless codec and inventory record. | Reviewing an extension route, or a model upgrade adds a row to its cell and `--check` reports the new declaration. |
| `tests/integration.rs` | The crate's one test target: every declared route routes, with and without the dialect; every other method, near miss and malformed parameter reaches exactly what an independent model of the rows says; a subject parameter changes no route; the one shadowing declaration; the secret opt-ins; the order-4 subject rules; the order-5 bucket bindings and the trailing-slash `heal/` row; the table catalog's four claims, compat alias rows and `{warehouse}` bindings; and every declaration matches its record; `integration/sts_form.rs` routes the STS form claim and its near misses and pins its floor, action, codec and record; `integration/extensions.rs` routes every extension discriminator under both selections, its value forms, its order against every key, `x-id` and the other discriminators, every near miss, the zip pair, and each operation's row, floor, action, codec, record and declared overlaps against the built table. | Changing a row, a selector, a template, a subject rule, a shared shape, the STS endpoint, or an extension row. |

## Verify

```bash
cargo xtask verify --crate rustfs-gateway-dialect-rustfs-admin
cargo xtask rustfs-admin-dialect --check
```
