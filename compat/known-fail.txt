# Known failures in the client compatibility matrix.
#
# Format, one per line:   <client>/<scenario>   <issue>   <reason>
#
# The issue reference is a required field, not decoration. It is copied into `compat/matrix.json`
# beside the cell, so a reader of the manifest can tell an excused gap from a new regression — and
# find who owns it — without reading a pull request. An entry with no issue is refused by
# `scripts/check_compat_matrix.sh`, because an excused failure nobody owns is a permanent one.
#
# This list only ever shrinks. The same guard compares it with the committed version and refuses a
# line that was not already there, so a regression cannot be silenced in the change that introduced
# it. Removing a line is always allowed and is what fixing a gap looks like.
#
# Every entry below is a gap in THIS repository — the reference backend does not register an
# operation the client needs, or admits it too narrowly. None of them is a client sending something
# S3 does not define. The two dispositions are completely different, so the distinction is recorded
# rather than left to be re-derived.
# Where a client does something the model does not require a server to accept, or the refusal is a
# deliberate default posture, the entry's own comment says so and its issue asks for the decision.

# The reference backend registers no GetBucketLocation, and minio-go asks a server for a bucket's
# region before it touches an object unless one is configured. mc has no region setting, so all
# five of its runnable scenarios stop at that one refusal.
mc/bucket-lifecycle          rustfs/gateway#627  GetBucketLocation is not registered
mc/small-object-roundtrip    rustfs/gateway#627  GetBucketLocation is not registered
mc/streaming-chunked-upload  rustfs/gateway#627  GetBucketLocation is not registered
mc/list-pagination           rustfs/gateway#627  GetBucketLocation is not registered
mc/sync-directory            rustfs/gateway#627  GetBucketLocation is not registered

# GetObject ignores Range: it answers 200 with the whole object where 206 and the requested slice
# are due. restic reads its packs by range, so this one gap fails a whole backup workflow.
boto3/range-download         rustfs/gateway#626  GetObject ignores the Range header
rclone/range-download        rustfs/gateway#626  GetObject ignores the Range header
restic/backup-restore        rustfs/gateway#626  GetObject ignores the Range header

# Only GetObject is reachable through a presigned URL, so a presigned PUT is refused 403.
boto3/presigned-put          rustfs/gateway#628  presigned PUT is not an admitted operation

# rclone stamps a modification time by copying an object onto itself, and CopyObject is not
# registered. The first mirror succeeds; every rerun fails and rclone then stops converging.
rclone/sync-directory        rustfs/gateway#629  CopyObject is not registered

# s3cmd preserves the source ACL on `cp` by writing it back with PutObjectAcl, and sends that body
# with no Content-MD5 or x-amz-checksum-*. The model marks PutObjectAcl checksum-required and the
# gateway enforces it; RustFS behind s3s answers the same request today.
s3cmd/copy-object            rustfs/gateway#912  PutObjectAcl without Content-MD5 is refused
# s3cmd signurl produces a SigV2 presigned URL, which the default SigV2Policy::HeaderOnly refuses.
s3cmd/presigned-get          rustfs/gateway#913  presigned SigV2 is refused under the default policy

# aws-sdk-dotnet percent-encodes the whole x-amz-copy-source, bucket/key separator included, and
# the gateway looks for the separator before decoding.
aws-sdk-dotnet/copy-object   rustfs/gateway#926  an encoded bucket/key separator in x-amz-copy-source is refused

# aws-sdk-java-v2's multipart client carries each part's CRC32 in a trailer; UploadPart only reads a
# part checksum from request headers, so a composite-checksum upload refuses every part.
aws-sdk-java-v2/large-multipart-upload  rustfs/gateway#929  a part checksum carried in a trailer is ignored
